# Xiuno_xw 插件开发指南

> 适用版本：Xiuno_xw 1.1.0（基于 Xiuno BBS 4.1.1 二开）
> 面向：插件开发、维护、修复

本文档讲解 Xiuno_xw 的插件机制，帮助你快速开发、更新和修复插件。

---

## 1. 插件机制总览

Xiuno_xw 的插件系统由两层组成：

| 机制 | 作用 | 实现 |
|---|---|---|
| **Hook（钩子）** | 在核心代码/模板的特定位置注入插件内容 | `// hook xxx.php` / `<!--{hook xxx.htm}-->` 注释 |
| **Overwrite（覆盖）** | 用插件文件替换同名核心文件 | `plugin/xxx/overwrite/` 目录 |

插件**安装**（跑 `install.php` 建表/改表）与**启用**（`conf.json` 里 `enable=1`）是两回事。

### 编译缓存机制

- 核心代码通过 `_include()` 加载，首次请求时把 **hook 内容合并进编译产物**（`tmp/` 目录）
- **改源码或插件后必须清空 `tmp/` 目录**，否则旧缓存不生效
- 生产环境 `DEBUG=0` 时用合并后的 `tmp/model.min.php`、`tmp/view_htm_*.htm` 等
- 开发时建议 `DEBUG=1`（`index.php` 里临时改），逐个加载不合并，方便调试

## 2. 插件目录结构

```
plugin/你的插件名/
├── conf.json          # 插件配置（必填，enable/installed 开关）
├── install.php        # 安装：建表、加字段（后台点"安装"时执行）
├── unstall.php        # 卸载：清理表、删字段
├── upgrade.php        # 升级：从旧版本升级
├── setting.php        # 后台设置页
├── setting.htm        # 后台设置页模板
├── hook/              # 钩子文件（放在这里才会被识别）
│   ├── xxx.php        # PHP 钩子（拼进核心 .php）
│   ├── xxx.htm        # HTML 钩子（拼进模板）
│   └── lang_zh_cn_bbs.php  # 语言扩展
├── model/             # 插件自己的函数库（hook 里 include）
├── overwrite/         # 覆盖的核心文件（按原路径放）
│   └── view/htm/xxx.htm
└── view/              # 插件静态资源（css/js/img）
```

**注意**：`hook/`、`overwrite/` 目录名固定；`install.php` 也是固定文件名（注意别拼错成 `install.php`）。

## 3. conf.json 配置

```json
{
    "name": "插件名",
    "brief": "插件简介",
    "version": "1.0.0",
    "bbs_version": "4.1.1",
    "installed": 1,
    "enable": 1,
    "hooks_rank": {
        "header_nav_forum_end.htm": -999
    },
    "overwrites_rank": {
        "view/htm/index.htm": 1
    },
    "dependencies": {
        "other_plugin": "1.0"
    }
}
```

| 字段 | 说明 |
|---|---|
| `installed` | 是否已安装（跑过 install.php）。**新装系统没有插件表时，别直接设 1**，否则查询不存在的表会报错 |
| `enable` | 是否启用。`enable=1` 且 `installed=1` 才参与 hook/overwrite 编译 |
| `hooks_rank` | 钩子优先级（数字越小越先执行，负数常用于提前覆盖默认逻辑） |
| `overwrites_rank` | 多个插件覆盖同一文件时的优先级，数字大的赢 |
| `dependencies` | 依赖的插件及最低版本 |

## 4. Hook 机制

### 4.1 钩子点

核心代码里用**注释**标记钩子点：

- PHP 文件：`// hook 名字.php`
- 模板文件：`<!--{hook 名字.htm}-->`

编译时，所有启用插件 `hook/名字` 文件的内容会被替换到钩子点位置。

### 4.2 PHP 钩子文件写法

```php
<?php exit;
// ↑ 必须保留这行！防止文件被直接访问，编译时会自动剥离
if($action == 'mytest') {
    echo 'hook 内容';
}
```

### 4.3 HTML 钩子文件写法

直接写 HTML/PHP 片段（不加 `<?php exit;`，因为不是独立文件）：

```html
<!--{hook 对应的钩子名}-->
<div class="my-plugin-block">
    <?php echo lang('my_plugin_text'); ?>
</div>
```

**注意**：HTML 钩子里的 PHP 代码会在模板的变量作用域中执行，可以直接使用 `$conf`、`$uid`、`$user` 等全局变量。

### 4.4 语言钩子（数组片段）

语言包是 `return array(...)` 结构，钩子点在数组内部：

```php
// 文件名：hook/lang_zh_cn_bbs.php
    'my_key'=>'我的文案',
    'my_key2'=>'我的文案2',
```

**必须以数组键片段开头**（不含 `<?php`），编译后合并进语言数组。语言钩子文件不要加 `exit;`。

## 5. Overwrite 机制

想整体替换某个核心模板/文件时，在插件里建：

```
plugin/你的插件名/overwrite/view/htm/index.htm
plugin/你的插件名/overwrite/admin/view/htm/setting_base.htm
```

文件路径 = 核心文件去掉 APP_PATH 前缀。编译时 `_include()` 会优先加载插件覆盖版本。

**注意**：
- 覆盖模板里必须保留原有 `<!--{hook xxx.htm}-->` 钩子点，否则其他插件的 hook 会丢失
- 覆盖文件也会被编译（hook 合并），改覆盖文件后同样要清 tmp

## 6. 生命周期

### 6.1 install.php（安装）

```php
<?php
!defined('DEBUG') AND exit('Forbidden');
$tablepre = $db->tablepre;
// 建表（幂等：IF NOT EXISTS）
$sql = "CREATE TABLE IF NOT EXISTS {$tablepre}mytable (
    id int(11) unsigned NOT NULL AUTO_INCREMENT,
    name char(32) NOT NULL DEFAULT '',
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8";
db_exec($sql);
// 给现有表加列（先检查是否存在）
!db_sql_find_one("SHOW COLUMNS FROM {$tablepre}user LIKE 'mycol'") AND db_exec("ALTER TABLE {$tablepre}user ADD mycol int(5) NOT NULL DEFAULT '0'");
```

### 6.2 unstall.php（卸载）

```php
<?php
!defined('DEBUG') AND exit('Forbidden');
$tablepre = $db->tablepre;
@db_exec("ALTER TABLE {$tablepre}user DROP COLUMN mycol");  // @ 容错，列不存在不报错
db_exec("DROP TABLE IF EXISTS {$tablepre}mytable");
message(0, '卸载完成');
```

### 6.3 upgrade.php（升级）

后台检测到版本升级时执行，用于增量更新表结构。

## 7. 常用 API 速查

### 7.1 请求与路由

| 函数 | 说明 |
|---|---|
| `param($key, $default)` | 取 GET/POST 参数 |
| `param(0)` / `param(1)` | 取路由段（`?thread-create-1.htm` → param(0)=thread, param(1)=create, param(2)=1） |
| `$method` | 请求方法：`GET` / `POST` |
| `url('thread-create-1')` | 生成 URL（`?thread-create-1.htm`） |
| `http_referer()` | 来源页 |

### 7.2 数据库

| 函数 | 说明 |
|---|---|
| `db_find($table, $cond, $orderby, $page, $pagesize)` | 列表查询 |
| `db_find_one($table, $cond, $orderby)` | 单条查询 |
| `db_insert($table, $arr)` | 插入 |
| `db_update($table, $cond, $update)` | 更新 |
| `db_delete($table, $cond)` | 删除 |
| `db_count($table, $cond)` | 计数 |
| `db_exec($sql)` | 原生 SQL（返回受影响行数） |
| `db_sql_find_one($sql)` | 原生 SQL 单条 |

条件数组示例：`array('uid'=>array('>'=>0), 'last_date'=>array('>'=>$time-3600))`

**表名前缀**：`$db->tablepre`（默认 `bbs_`）。

### 7.3 缓存与配置

| 函数 | 说明 |
|---|---|
| `cache_get($key)` / `cache_set($key, $val, $life)` | 通用缓存（file/redis/memcached） |
| `kv_get($key)` / `kv_set($key, $val)` | KV 持久存储（bbs_kv 表） |
| `kv_cache_get($key)` / `kv_cache_set($key, $val)` | KV + 缓存双层 |
| `setting_get($key)` / `setting_set($key, $val)` | 站点设置（存 bbs_kv 的 setting 键） |

### 7.4 响应与提示

| 函数 | 说明 |
|---|---|
| `message($code, $text)` | 输出提示。AJAX 返回 JSON，否则渲染提示页。`$code=0` 成功，负数错误，字符串定位到表单字段 |
| `message(0, jump($text, $url))` | 成功并跳转 |
| `lang('key')` | 取语言文案（语言钩子里加） |
| `form_text/select/radio_yes_no(...)` | 后台表单辅助（自动生成 name/value 属性） |

### 7.5 用户与权限

| 函数 | 说明 |
|---|---|
| `$uid` / `$user` / `$gid` | 当前用户（全局变量） |
| `user_read($uid)` | 读用户 |
| `user_read_cache($uid)` | 读用户（带缓存） |
| `user_login_check()` | 未登录则跳转登录页 |

## 8. 前台与后台钩子常用位置

### 前台

```
header_nav_forum_end.htm    导航菜单结束
index_site_brief_after.htm  首页侧栏
thread_message_after.htm    帖子内容后
post_message_after.htm      发帖框后（编辑器工具栏区）
footer_js_after.htm         footer JS 后（可加载自定义 JS/CSS）
footer_end.htm              footer 结束
```

### 后台

```
admin_header_css_after.htm  后台 head CSS 后
admin_footer_js_after.htm   后台 footer JS 后
admin_setting_start.php     设置页（加 tab 用）
admin_setting_end.php       设置页 action 分支
```

**查找钩子点**：在核心文件里 `grep -rn "hook " route/ view/htm/ admin/ model/`，或在模板里搜索 `<!--{hook`。

## 9. 调试技巧

### 9.1 快速定位问题

```php
// 临时输出调试信息（用完删除）
file_put_contents(APP_PATH.'tmp/debug.log', var_export($var, true)."\n", FILE_APPEND);
```

### 9.2 常见坑

| 坑 | 说明 |
|---|---|
| **改了不生效** | 99% 是没清 `tmp/`。改完源码/插件务必清 tmp 或开 `DEBUG=1` |
| **PHP 8 兼容** | 数据库驱动必须用 `pdo_mysql`（`db_mysql` 在 PHP 7+ 是空壳）。`mysql_*` 函数已移除 |
| **后台按钮文字色被覆盖** | `<a role="button">` 无 href 时，Bootstrap 的 `a:not([href]){color:inherit}` 优先级更高，需显式覆盖 |
| **表单提交 CSRF 失败** | 表单必须包含 `<?php echo csrf_token_hidden();?>`，或确认 `var csrf_token` 全局变量存在（footer 已输出） |
| **验证码校验** | 用 `captcha_check()`，验证码存 session，用后即焚 |
| **hook 文件加了 exit 但没生效** | PHP hook 必须是 `<?php exit;` 开头（保证独立访问安全 + 编译剥离）；HTML hook 不要加 |
| **登录态异常** | 游客纯浏览不建 session；登录/验证码会话才会写入。调试登录时注意这点 |
| **在线人数虚高** | 检查是否产生了大量 session（测试访问会产生，可在后台调短 `online_hold_time`） |

### 9.3 发布与上线

- 版本号统一在 `index.php` 的 `$conf['version']` 定义
- 打包发行版：`plugin/` 目录排除在发行版外（插件单独分发）
- 上线前清空 `tmp/`、`log/`，删除 `conf/conf.php`（安装器会重新生成）

## 10. 完整示例：最小插件

### 结构

```
plugin/xn_hello/
├── conf.json
└── hook/
    └── index_site_brief_after.htm
```

### conf.json

```json
{
    "name": "打招呼",
    "brief": "首页显示一句问候",
    "version": "1.0.0",
    "bbs_version": "4.1.1",
    "installed": 1,
    "enable": 1,
    "hooks_rank": [],
    "overwrites_rank": [],
    "dependencies": []
}
```

### hook/index_site_brief_after.htm

```html
<div class="card">
    <div class="card-body">
        <?php if($uid) { ?>
            你好，<?php echo htmlspecialchars($user['username'], ENT_QUOTES); ?>！
        <?php } else { ?>
            欢迎来到本站，<a href="<?php echo url('user-login'); ?>">登录</a> 后体验更多功能。
        <?php } ?>
    </div>
</div>
```

### 启用步骤

1. 目录放入 `plugin/xn_hello/`
2. 后台「插件」→ 本地插件 → 安装 → 启用
3. 清空 `tmp/`
4. 刷新首页

## 11. 插件适配清单（本系统特殊点）

开发/修复插件时对照以下清单，避免踩坑：

- [ ] 表单是否含 `csrf_token_hidden()`（前台路由 POST 有 CSRF 校验）
- [ ] 是否误用 `tinymce`（当前系统默认无编辑器，需兼容 `#message` textarea）
- [ ] Modal/按钮用的是 Bootstrap 4 语法（`data-toggle`，不是 `data-bs-toggle`）
- [ ] 图标用系统 `icon-*`（避免依赖未加载的 Line Awesome `las la-*`）
- [ ] PHP 8 兼容（pdo_mysql、无 `mysql_*`、数组访问 bool 的报错）
- [ ] 无 href 的 `<a role="button">` 文字颜色需显式设置
- [ ] 语言包：新增文案加到 `hook/lang_zh_cn_bbs.php` 等（5 语言）
- [ ] 后台 tab 按钮用 `btn btn-secondary`（主题已统一配色）
